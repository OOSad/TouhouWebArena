### Sparring AI: Velocity-Obstacle Rewrite
- [x] **Replaced the hand-tuned rule chain with a velocity-obstacle move scorer** (`scripts/ai/rudimentary_ai.gd`):
  - The old bot ordered rules by priority (`_check_edge_escape` > `_calculate_evasion_vector` > enemy alignment), which is why it looked robotic: the hard wall at `SAFE_MIN_X`/`SAFE_MAX_X` made it refuse edge lanes even when an edge lane was its only safe option.
  - Approach borrowed from [twinject](https://github.com/Netdex/twinject)'s documented "constrained velocity obstacle" dodger - the underlying [velocity obstacle](https://en.wikipedia.org/wiki/Velocity_obstacle) concept is published robotics work, so it was reimplemented from the idea. **twinject itself is GPL-3.0: do not port its source into this repo.**
  - ZUN's actual PoFV AI is compiled into `th09.exe` and is not recoverable via `thtk`/`truth` (those decompile ECL bullet patterns, not opponent decision-making). Community notes do document that it is deliberately short-horizon and reactive, which is what the difficulty dials imitate.
  - `_collect_hazards()` normalizes bullets/lasers/enemy bodies into flat records behind an early vertical gate, so the dynamic `in`/`get()`/`is` lookups are paid once per frame instead of per candidate.
  - `_pick_best_move()` scores all 18 commandable velocities (9 headings x focus) by time-to-collision, breaking ties on closest approach, firing-line alignment, engagement height and *soft* edge pressure.
  - `configure_difficulty(1-9)` scales lookahead horizon, decision rate, hazards tracked and scoring noise - perception and reflexes, not separate rule sets. **Not yet wired to any menu.**
  - Two things the greedy window cannot see are explicit constraints: Focus is suppressed near wide hazards (`WIDE_HAZARD_RADIUS`), and clearance uses diminishing returns.
  - Legacy rule chain retained behind `use_velocity_obstacle = false` for A/B comparison.
- [x] **Perception fixes found by playtesting** (each one was a legacy assumption surviving into a system built on different premises):
  - Extra Attack nodes keep motion in a private `_velocity` (`sakuya_extra_knife`, `sakuya_knife`, `hakurei_amulet`, `youmu_slash_wave`). None matched the old lookup chain, so all four fell through to a "falls straight down at 240 px/s" default - for a dagger crossing the field horizontally that prediction points the wrong way, and the bot ignored them. Velocity now also reads `_velocity`, then falls back to measuring the node's own frame-to-frame motion; radius falls back to the real collision shape. **This blind spot predated the rewrite** - the old rule chain shared it, but drifted constantly and dodged these by accident.
  - Candidate velocities were fed to the collision test raw, so from the bottom wall a "dive downward" heading scored as a clean escape while moving the bot zero pixels. `_effective_velocity()` now limits each heading to the room actually left in that direction. Edge pressure covers all four walls (it was X-only, which is what parked the bot at the back).
  - Positional terms were judged one decision tick ahead (~9px), making every positional gradient smaller than the flat hysteresis bonus. Now judged over a fixed `POSITION_PROJECTION` of 0.25s.
  - Hazard collection gated at 50px below the player, so a bullet the bot had just dodged stopped existing and it would reverse into it. Collection is now omnidirectional (`HAZARD_SCAN_RADIUS`, 460px) on top of the legacy band.
  - The tracking cap kept the *nearest* hazards, so in dense danmaku all 48 clustered around the bot and escape routes went unevaluated (this caused visible overshoot). Ranking is now by predicted closest approach (`threat_sq`), computed in the collection pass that already has velocity to hand.
  - The legacy single baseline height survived as a weight costing ~17 points to stand mid-field, about a third of the clearance term - the bot was paying real points to dodge upward and confined itself to the bottom fifth of the screen. Replaced with a free engagement band (y 420-856).
  - `EarthLightRay` nodes sit at `(x, 0)` - the top of the field - but the hazard is a column spanning the full height. Ranking by straight-line distance to that node scored a laser directly overhead at ~490,000 against a few thousand for nearby pellets, so the tracking cap culled it first in exactly the busy moments it gets fired in, and the bot walked into it without ever seeing it. Lasers now rank on horizontal gap only. **Watch for this shape of bug in any future hazard whose node position does not represent its hitbox.**
- [x] **Second-ply rollout** (`_escape_potential()`): projects the world forward one `rollout_step` and reports the best survival still reachable from where a move lands, so a move into a closing pocket loses to one that keeps its options. Runs only when something is actually threatening and only for the leading `rollout_candidates` (3), with hazard positions advanced once and shared. Approximation: hazards advance in a straight line, so wall bounces and the curved motion modes are not re-simulated during the rollout.
- **Measured survivability** (AI vs AI, Sakuya x Marisa, user-run): legacy rule chain ~1:11 -> 0:53 (first VO pass, perception bugs) -> 1:28 -> 1:50 -> **~2:20-2:30** after the rollout, engagement band, laser ranking and Lily White retune. PoFV's own bots push 6:00, but the patterns and densities differ, so treat that as a loose reference rather than a target.
- [x] **Pruned legacy rule-based evasion chain & enhanced enemy velocity tracking**:
  - Removed dead `use_velocity_obstacle` export, the 150-line legacy priority evasion functions (`_calculate_evasion_vector`, `_evaluate_dodge_candidate`, `_calculate_enemy_alignment_vector`, `_check_edge_escape`, `_should_focus`), dropping `rudimentary_ai.gd` by ~270 lines.
  - Upgraded enemy body hazard tracking: enemy bodies (fairies, bosses) now track velocity and sample position deltas across frames rather than defaulting to stationary phantoms (`vel = Vector2.ZERO`), enabling the VO scorer to predict incoming fairy collisions and steer cleanly out of their way.
  - Aligned unit tests in `test_ai_hazard_evasion.gd` to test active evasion under velocity obstacle physics (51/51 tests pass). All 23 regression test suites passing green.
- [x] **Diagnosed & Fixed: AI Corner Trapping & Multi-Heading Rollout Mobility**:
  - *Corner Proximity Penalty*: Previously, edge distance was computed as `minf(dist_x, dist_y)`, meaning being trapped in a corner (pinched against both side wall and bottom floor) cost the exact same penalty as standing against a single flat wall in the center of the field. Now calculates `dist_x` and `dist_y` independently, penalizing each wall individually, and applies a dedicated quadratic corner penalty (`CORNER_MARGIN = 130.0`, `W_CORNER = 35.0`, `W_BOTTOM_CORNER_EXTRA = 35.0`) when entering 2-wall corner pockets (up to -120 pts in bottom corners), strongly urging the bot back toward open center field.
  - *Rollout Multi-Heading Mobility*: `_escape_potential()` previously broke on the very first direction that had `survival >= lookahead_horizon`. A corner landing with 7 directions blocked and only 1 open escape corridor scored the exact same as an open-field landing with all 8 directions clear. Now skips directions blocked by walls (`follow_vel.length() < spd_normal * 0.25`) and scores combined multi-heading branching mobility (`best_1 * 0.60 + best_2 * 0.25 + best_3 * 0.15`), heavily discounting corners and dead ends.
  - Difficulty selector dropped per user design decision (bot remains authentically at standard calibrated skill).
  - Verified with new unit test `test_corner_avoidance_and_escape()` in `test_ai_hazard_evasion.gd`. All 23 test suites pass cleanly.
- [ ] **Known remaining gaps, in rough order of value** (deliberately stopped here - diminishing returns):
  - Curved bullets are linearized. `DanmakuBullet` has `DECEL_AND_HOME`, `EXPANDING_ORBIT`, `CURVE_THEN_LINE` and `ELLIPSE_THEN_LINE`; the predictor extrapolates all of them as straight lines from instantaneous velocity, so every spellcard using those is mispredicted.
  - The bot makes no defensive use of its own kit - spellcards fire on a random timer rather than when it is cornered.
  - `lookahead_horizon` (1.2s) is now the binding constraint on foresight, not perception: enemy pellets travel ~160 px/s, so they cover only ~195px in the window while the scan radius is 460px. Raising the horizon costs linearly.
  - `W_HYSTERESIS` (3.0) is comparable to several real positional gradients and has twice come close to vetoing a genuine preference. Worth revisiting if the bot ever looks stuck.

### Lily White Barrage Retune
- [x] **Claw strands were overlapping by construction.** Prongs sat at `-13/0/+13` degrees with `angle_jitter_deg = 7.0`, so the `-13` prong covered `[-20, -6]` and the `0` prong covered `[-7, +7]` - the ranges intersect, so neighbouring prongs landed on each other every wave and across the barrage all three strands smeared into one solid wall. PoFV reference footage shows clearly separated strands with navigable lanes. Now `claw_spread_deg = 24.0` / `angle_jitter_deg = 2.0`, plus `speed_jitter` 35 -> 15 so the beads stay evenly spaced along each strand. **Invariant: `angle_jitter_deg` must stay well under half of `claw_spread_deg`.**
- [x] **Density had drifted 50% above the documented design.** Commit `22a2973` rescaled the three cadence values together (`32/0.105/6.0` -> `48/0.070/4.0`) for a smoother sweep. Duration (3.36s) and swept arc (192 degrees) both survive that rescaling; total bullets (`count x 12`) does not, so output went 384 -> 576 silently and the catalog was never updated. Reverted to `32 / 0.105 / 6.0`. For scale the per-field bullet cap is 350, so at 576 a single barrage could saturate the field and start dropping other danmaku.
- Tests now pin duration, arc and bullet count as three separate assertions so a future cadence pass cannot move density without failing.

### Extra Attack Placement Now Syncs Across Clients
- [x] **Every client was rolling an Extra Attack's landing spot for itself.** The attack packet carried only a `has_extra_attack` bool; the actual position came from `randf_range` inside `MoteDispatcher.send_attack_between_fields`, run independently on each machine. Marisa's Earth Light Ray therefore came down in a different column on each screen - the aggressor would see a dodge that the defender never had to make. Where a big, slow, telegraphed attack lands is **attack identity, not per-bullet jitter**, so it belongs on the wire (small bullet spray still does not - that stays local on purpose).
- [x] **The roll moved to the client that owns the attack.** `MoteDispatcher.roll_extra_attack_targets(sender_char, rank)` is now called once in `arena._on_p1/p2_attack_sent` and the resulting `PackedVector2Array` is sent with the attack; a non-empty array is used verbatim, an empty one means a local match and is rolled at the far end as before. **A shared seeded RNG was deliberately not used** - it would only stay in step while both clients spawned Extra Attacks in identical order, and the two players' chains interleave differently under latency.
- [x] **Two things rode along that were desyncing for the same reason:**
  - Cirno's Extra Attack rolls a rank-scaled *count* (1-2 at rank 1, 3-4 at rank 22), so the two clients could disagree on how many stalactites were even on the field. The count is now settled by the length of the rolled array.
  - `rank` was never in the packet at all, so the receiving client passed `rank = 1` into `setup_rank()`. Youmu's dark spirit lives 1.0s at rank 1 and 2.0s at rank 22 - the defender was seeing a materially shorter hazard than the attacker. `sender_rank` is now sent.
- [x] **Reimu's Yin-Yang Orb rolled its own opening toss in `_ready()`.** Direction and speed there decide every wall bounce for the orb's whole life, so the orb desynced even once its spawn point matched. It now takes `setup_variation(seed)`, seeded in `Playfield.spawn_extra_attack` from a hash of the already-synced landing spot - so it costs nothing extra on the wire. **Any future Extra Attack that randomizes its own trajectory should use this same hook rather than a bare `randf()`.**
- Sakuya needed no change: her daggers fly from the fairy's death spot under their own power with a fixed stagger, so they were already deterministic. `roll_extra_attack_targets` returns an empty array for her on purpose.
- Spectator events and replays are JSON and have no `Vector2`, so the roll travels those two paths through `targets_to_flat` / `targets_from_flat` as a flat `[x, y, ...]` list.
- **The RPC signature changed** (`rpc_attack` gained `extra_targets` and `sender_rank`), so both peers must be on the same build - relevant when cutting the next playtest release.
- [x] **The same bug in spellcard- and boss-driven Extra Attacks is now fixed too, and it cost nothing on the wire.** `DanmakuExtraAttackStep` rolled `spawn_pos` and `tilt_angle` per client at execution time. Shipping a whole pattern's worth of points in a packet would have been the wrong shape; instead the pattern is made *reproducible* and seeded from data both clients already hold:
  - `SpellcardData.execute_sequence()` takes an optional `pattern_seed`. Above `-1` it builds a `RandomNumberGenerator` and hands **each step its own derived generator** (`step_rng.seed = rng.randi()`) rather than sharing one. A step that `await`s must not have its draw order interleaved with another step's.
  - `DanmakuStep` gained `set_sync_rng()` / `take_sync_rng()`. A step opts in by calling `take_sync_rng()` **on its first line, before any `await`** - step resources are shared between both playfields, so pulling the generator into a local is what stops a second concurrent `execute()` swapping it out mid-pattern. `execute()`'s signature is unchanged, so the other ~25 step types needed no edit and keep drawing from the global RNG on purpose.
  - Player casts seed from `Playfield._round_seed + _spellcard_cast_count * 6271`, mirroring the existing `_boss_spawn_count` pattern. **A field only ever receives spellcards from its one opponent**, so that counter advances in the same order on both clients with nothing sent. Boss patterns draw their seed from `BossCharacter._rng`, which was already synced for attack selection - the draw sits at a fixed point in that RNG's order so it cannot shift the picks that follow.
  - The per-wave origin jitter in `execute_sequence` was desyncing too and is now seeded: it moves the whole wave, so it is "where the attack comes from", not bullet jitter.
  - `DanmakuExtraAttackStep` also feeds `setup_variation()` now, so orbs spawned by a boss get the same synced toss as the fairy-chain ones.
- [x] **Removed `alternate_toss_direction` from `DanmakuExtraAttackStep`, which had never done anything.** It set `attack_node.velocity.x` *before* `add_child()`, so (a) `velocity` was still `Vector2.ZERO` and `absf(0.0)` kept it zero, and (b) `YinYangOrb._ready()` then overwrote `velocity` wholesale. Offered as a gameplay choice (make the boss's orbs alternate left/right, or drop the flag); **the user chose to drop it**, so the orbs keep picking their own synced direction and nothing on screen changed. The three boss spellcards that stored `alternate_toss_direction = true` were cleaned up too. **General rule this is an instance of: an attack node that rolls its own trajectory in `_ready()` cannot be steered by writing to its properties before `add_child()`** - use a `setup_*` method, the way `setup_variation()` and `setup_rank()` do.

### Test Infrastructure
- [x] **The runner could not report failures.** 15 of 23 suites call `quit(0)` unconditionally and report only through Godot's bare `assert()`, which aborts the failing function, prints to stderr, then lets the script reach that `quit(0)`. Plain `ERROR:` lines stay allowed on purpose: `test_replay_system` calls `push_error()` to exercise a negative path and Godot reports leaked resources at teardown. Verified by injecting a failing assertion and confirming it reports red. Full suite: 23/23 in ~31s. Override Godot's path with the `GODOT` env var.
- [x] **`test_grazing.gd` was failing against working code.** Its factories added nodes to the tree but never called `_ready()`; these suites run inside `SceneTree._init()` and quit before a frame is processed, so Godot never fires `_ready()` and every `@onready` var stayed null. **Any new suite must call `_ready()` by hand**, as `test_ai_hazard_evasion.gd` does. A second assertion then blamed the graze jitter for ordinary bullet travel (`speed` defaults to 240 px/s); pinned speed to zero so only the jitter can move the bullet.
- [ ] **Optional:** the 15 bare-`assert()` suites still cannot distinguish "12 assertions passed" from "aborted at the first one" in their own output. The runner catches failures now, so this is cosmetic. Converting them to the `assert_true` + counter style the other 8 use is mechanical, roughly an hour, and only worth doing if the current failure output proves too coarse in practice.

  - **Root Cause**: `BossCharacter` (`scenes/enemies/boss_character.gd`) picked its attack pattern (`attack_patterns.pick_random()` under `AttackSelectionMode.RANDOM` - the default for every existing boss) and its hop direction/distance/timing (`randf()`/`randf_range()`/`randi_range()`) using Godot's plain global RNG.     - `BossCharacter` gained its own `_rng: RandomNumberGenerator`, seeded from that value in `setup()` (falls back to `randomize()` if no seed is passed, e.g. existing tests). Every internal random call - attack-pattern pick, `_target_attack_count`/`_target_duration` rolls, hop direction/distance/vertical jitter in both `_perform_hop()` and `perform_cast_hop()` - now goes through `_rng` instead of the global functions. `Array.pick_random()` doesn't accept a custom generator, so pattern selection was rewritten as a manual `_rng.randi_range(0, size - 1)` index pick.
  - Individual `DanmakuStep` resources (dagger circle jitter, pellet scatter angles, etc.) intentionally still use unseeded global randomness per the user's call - only the boss's own decisions needed to match.
